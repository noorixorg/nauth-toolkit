## Fixes

- **`migrations.autoRun: false` now works on NestJS.** `AuthModule` ran migrations on every
  boot regardless of the setting. It now skips them, as `NAuth.create()` always has, so a
  release task or Kubernetes Job can own migrations.

{/* truncate */}

```typescript
migrations: { autoRun: false },
```

- **`mfaFirstEnabled` and `mfaMethodAdded` now fire.** They were silent on every framework,
  along with the built-in emails behind them. If your `emailNotifications.suppress` leaves
  them enabled, users will start receiving those emails after upgrading.
- **A phone change during SMS MFA setup reports what it removed.** Supplying a different
  `phoneNumber` already deleted the SMS devices tied to the old number; now
  [`mfaDeviceRemoved`](/docs/api/core/hooks/mfa-device-removed-hook) fires and
  [`phoneChanged`](/docs/api/core/hooks/phone-changed-hook) carries `deactivatedMFADevices`
  and `mfaDisabled`, the same as a profile update. `VERIFY_PHONE` phone collection behaves
  the same way. See [SMS MFA](/docs/guides/mfa/sms).

No action needed on upgrade.
